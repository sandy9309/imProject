# 房間座標與牆外回復修正

## 問題

第二次啟動時，MRUK／手動牆可能使用新的世界座標，但後端仍回傳上次的 Unity 世界座標。
家具可能因此出生在牆外。舊判斷只把牆當成雙向障礙，沒有分辨房內外，所以牆外家具會被阻止拉回房內。
手動牆啟用時，記憶體中的 MRUK room 也可能繼續執行 `IsPositionInRoom`，形成看不見的舊房間阻擋。

## 現在的規則

- 場景明確標記目前使用 `ScannedRoom` 或 `ManualWalls`，兩種邊界不混用。
- 手動牆角形成房間多邊形；家具四個底面角落都必須位於多邊形內。
- 掃描房間只讓實體 `WALL_FACE` 與 `INNER_WALL_FACE` 阻擋家具。Meta 用來分隔開放空間的 `INVISIBLE_WALL_FACE` 不建立 Collider，也不使用包含該概念邊界的 `IsPositionInRoom` 限制。
- 每次重建牆面增加 geometry version。家具下次驗證時會丟棄舊房間快取；若舊安全位置失效，從目前房間中心尋找合法位置。
- 新位置以目前房間參考座標保存，API 欄位 `coordinateSpace` 為 `placement-local-v1`。
- 沒有 `coordinateSpace` 的舊資料視為 `world-v0`；成功載入及再次儲存後會轉成新版。
- 新增但尚未擺放的家具生成在使用者前方，再由放置驗證調整到房內。
- 家具被牆擋住後，搖桿／抓取累積量會同步到實際接受的位置，反向操作不必先抵銷牆後方的隱藏位移。
- 返回專案 ID 畫面時立即停用並清除場景中的虛擬家具，避免看見上一個專案或留下隱形碰撞。

## 部署與驗收

Unity 與 `imProject-Yang/MyFurnitureTest` 後端必須一起更新，否則舊後端不會保存 `coordinateSpace`。

1. 建立或掃描房間，生成家具，移動後等待自動儲存。
2. 完全關閉並重開 App，載入同一房間與專案，確認家具仍對齊牆面。
3. 持續把家具推向牆，再立刻反向拉，確認家具立即離牆。
4. 重建手動牆後載入舊家具，確認家具被移到房內，且無法由牆角推出房外。
5. 先載入 MRUK 房間再切換手動牆，確認舊 MRUK 邊界不再形成隱形阻擋。
